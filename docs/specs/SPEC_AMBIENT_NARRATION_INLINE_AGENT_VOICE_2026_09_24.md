# SPEC: Ambient narration — render inline, in the agent's voice, with a trailing tag

**Date:** 2026-09-24
**Status:** implemented in PR #3719 — Q1 resolved as live-only (not persisted — corrected after review), Q2–Q3 as recommended; Q4 (deterministic template instead of Haiku) still open. Not yet observed in a live app.
**Builds on:** PR #3169 (`feat(agent-pane): narrate backgrounded tasks into the conversation`),
`docs/reports/REPORT_AGENT_PANE_PROGRESS_INDICATORS_CONSOLIDATION_2026_09_09.md` §8.3
**Scope:** frontend rendering + where the narration lives. No backend change.

---

## 1. Problem

Ambient narrations — short lines AgentMux itself generates about something it did
(today: "a Bash call was detached to the background") — currently render as a
**separate labeled strip**, not as part of the conversation:

- `AmbientNarrationRow` is mounted in `agent-view.tsx` (~L2565) as a sibling
  directly above `ActivityDock`, outside the document scroll region. It does not
  scroll with the transcript and is not positioned at the point in the
  conversation it refers to.
- Each line is prefixed with a boxed, uppercase **`AMBIENT`** chip and set in a
  smaller (12px), `--secondary-text-color` face — it reads as system chrome, a
  status row, not as the agent talking.
- State lives in `useAmbientNarration`: a 5-item signal, per-pane, gone on reload.

The stated intent of #3169 was that these "appear like they are coming from the
model". The shipped result reads as a labeled doc item instead.

## 2. Goal

An ambient narration should look like a normal agent message: same position in
the flow, same typography, same colour as the agent's own prose. The only
difference is a **small `ambient` tag at the end of the line**.

Non-goals: changing when narrations fire, what the backend prompt says, the RPC
or the `ambient-narration` broadcast, or adding new narration kinds.

## 3. Design decision that must stay fixed: the tag remains

The tag is not decoration and is not removed by this spec — it moves from the
front to the end and gets quieter. The reason is unchanged from the comment in
`AmbientNarrationRow.tsx`: the model did not write these lines and the CLI
transcript does not contain them. Untagged, a line in the agent's voice reads back
later — to the user, or to an agent debugging its own conversation — as something
the model claimed. A trailing tag keeps that provenance while letting the sentence
itself read as continuous prose.

Design constraints on the tag:
- Trailing, inline with the last line of text (not a separate line, not a badge
  in the gutter).
- Small and low-emphasis: ~10px, `--secondary-text-color`, reduced opacity, no
  accent colour (it marks provenance; it does not ask to be clicked).
- Present in all states — it must survive theme changes and copy-paste-free
  (see §6.4 on copying).
- Has a `title` / accessible label: "Generated by AgentMux, not by the model".

## 4. Design

### 4.1 Data: a distinct document node type

Add `AmbientNarrationNode` to the `DocumentNode` union in
`frontend/app/view/agent/types.ts`:

```ts
export interface AmbientNarrationNode {
    type: "ambient_narration";
    id: string;          // `ambient-<dedupe_key or timestamp>` — stable, for dedupe
    kind: string;        // backend prompt selector, e.g. "background_task"
    text: string;
    timestamp: number;   // unix ms of arrival
}
```

**Why a new node type rather than a `MarkdownNode` with `metadata.ambient`:**
`MarkdownNode` is "raw markdown from agent output". Code that walks the document
and assumes markdown == model text (reducer `StreamFlush` merge logic at
`agent-document/reducer.ts` L159/L556, message copy, token estimates, any future
"last assistant message" logic) would silently start treating AgentMux's own
sentence as model output — exactly the misattribution §3 exists to prevent. A
separate `type` makes every existing `switch`/`=== "markdown"` ignore it by
default. Precedent for a frontend-originated, non-transcript node in this union:
`MemoryReinjectionNode`, `SessionOutcomeNode`.

### 4.2 Rendering: reuse the agent-prose styling

Add an `ambient_narration` branch in `virtualization/DocumentRow.tsx` next to the
`markdown` branch (~L206), rendered by a new small `AmbientNarrationBlock`
component. It must:

- Use the same wrapper class as agent text (`.agent-markdown-block` in
  `styles/_document-nodes.scss`, ~L78) so font size (`--font-agent-size`),
  colour (`--main-text-color`), padding and selection behaviour are inherited,
  not re-specified. The current 12px / secondary-colour styling in
  `AmbientNarrationRow.scss` is dropped.
- Render `text` as plain text (the backend prompt already demands "plain text
  only — no markdown"), then a trailing
  `<span class="ambient-narration-tag">ambient</span>` inline after it, separated
  by a normal space so it wraps with the text rather than pinning to the right
  edge.
- Participate in the existing hover-peek (`useNodePeek` / `PeekOverlay`) so it
  shows its timestamp like other node kinds (see `SPEC_TRANSCRIPT_NODE_HOVER_PEEK_ALL_KINDS_2026_08_25`),
  plus a line stating the source: "AgentMux ambient narration (`<kind>`)".
- Honour `useAgentDormant` only if it does any non-trivial work; plain text needs
  no throttling.

### 4.3 Data path: into the document store

Replace the `AmbientNarrationRow` strip with document insertion:

1. `useAmbientNarration(blockId)` keeps its subscription to
   `WpsEvent.AmbientNarration` and its malformed-payload handling, but instead of
   holding a 5-item signal it hands each accepted narration to a callback that
   dispatches it into the pane's document as an `AmbientNarrationNode`.
2. Insertion is a direct `paneModel.dispatchDoc({ type: "StreamFlush", newNodes: [node], updatedNodes: [] })`,
   the same way `postSystemNotification` posts its line — **not** through
   `StreamFlushQueue`. (Revised from the first draft of this spec, which said
   queue.) The queue's flush also dispatches `StreamFlushObserved` to the pane as
   turn activity, and AgentMux narrating itself is not evidence the model is
   doing anything (§6.3). The queue's `pushDockNodeStatus` side effect is
   likewise avoided.
3. Node ids are `ambient-<arrival ms>-<seq>` (unique per arrival). Carrying the
   backend's `dedupe_key` through the broadcast so a re-delivered event maps to the
   same id is a possible follow-up (a single extra JSON field in `websocket.rs`
   ~L1385); the first implementation does not touch the backend.
4. Delete `AmbientNarrationRow.tsx` / `.scss`, and the `<AmbientNarrationRow>`
   mount in `agent-view.tsx`. Remove the `MAX_RETAINED = 5` bound — the document
   store already owns retention and virtualisation, and an in-flow node must not
   be silently dropped when the sixth arrives.

### 4.4 Position in the flow

The narration arrives asynchronously — seconds after the tool call it describes,
possibly mid-stream. Appended at arrival time it lands after whatever node is last
in the document. Because `StreamFlush` looks up updates by id, a still-streaming
assistant message keeps growing *above* the narration; a following message opens a
new node below it. That is acceptable and honest (the line appears when it was
generated). We do **not** try to splice it directly after the originating tool
node: that would make the transcript order differ from arrival order and would
break the append-only assumption the virtualiser relies on. Open question Q2.

## 5. Behaviour that must not change

- Best-effort: no state or UI change is gated on a narration arriving. The
  existing suppress-if-already-finished check in `websocket.rs` stays.
- Narrations never enter the CLI transcript and never reach the model's next turn.
  Inserting into the *view* document store must not be confused with sending to the
  CLI — nothing in this change touches the send path, `agent_input`, or
  `memory-reinjection`.
- Trigger, prompt (`narration_prompt`), semaphore and gateway keying are untouched.

## 6. Risks and things to verify during implementation

1. **Document consumers that assume a closed set of node types.** Grep every
   `switch (node.type)` / exhaustive `never` check over `DocumentNode` (reducer,
   `parseHistoryLines`, virtualiser height estimation, search, export, history
   reader). A new union member will fail typecheck at exhaustive sites — good —
   but non-exhaustive `default:` branches may need a decision.
2. **Virtualiser row-height estimate.** Plain text with an inline tag wraps; the
   estimator for unknown node types must not assume a fixed single-line height.
3. **Turn / working-indicator state.** Confirm `turnPhase`, `isPaneWorking`, and
   the liveness reducers do not treat "a new node appeared" as evidence of model
   activity (`turn-liveness-*` tests are the place to look). An ambient node
   arriving on an idle pane must not flip it to working, and one arriving mid-turn
   must not reset a liveness timer.
4. **Copy / select.** Users will select-and-copy conversation text. The tag should
   be `user-select: none` **or** included — decide deliberately. Recommendation:
   include it in copied text (so a pasted transcript keeps the provenance), i.e.
   do not set `user-select: none`.
5. **Persistence — corrected after review (Codex P2 on #3719).** An earlier
   draft of this spec claimed the document snapshot would carry ambient nodes across
   a pane reopen. It does not: `useSnapshotPersistence.ts` deliberately omits
   `nodes[]` and the document is rebuilt from the NDJSON output log, which ambient
   broadcasts never enter. So an `ambient_narration` node is **live-only** — gone on
   reopen and absent from Agent History — and `live-feed.ts` rolls it off with its
   turn (only shell nodes block roll-off), exactly as it already does for the other
   live-only decoration rows (stderr, notifications, "Interrupted"). Q1.
6. **Accessibility.** The tag must be readable by a screen reader in-line
   ("…, ambient") or replaced by an `aria-label` on the row; do not rely on visual
   position alone.

## 7. Tests

- `useAmbientNarration.test.ts`: keep malformed-payload / whitespace / unsubscribe
  cases; replace the retention-bound case with "each accepted narration invokes the
  insert callback exactly once, in order, with a stable id".
- New `AmbientNarrationBlock.test.tsx`: renders text in the agent-prose wrapper;
  renders exactly one trailing `ambient` tag after the text; tag is inside the same
  block element, not a sibling row.
- `stream-flush-queue.test.ts`: an `ambient_narration` node pushed via
  `pushNewNode` triggers no `DockNodeStatusCommand` and no `AmbientNarrateCommand`
  (guards against a feedback loop).
- Reducer test: `StreamFlush` with an ambient node appends without disturbing an
  in-progress markdown node's streaming update.
- Turn-liveness test: an ambient node on an idle pane leaves `turnPhase` idle.
- Manual (real app, required before merge — #3169 shipped without it): trigger a
  backgrounded Bash call, confirm the line appears in-flow, scrolls with the
  transcript, matches the agent's font and colour, and ends with the small tag;
  check light and dark themes.

## 8. Open questions (need a decision)

- **Q1. Persistence.** Should narrations survive pane close/reopen? **Resolved:
  no — live-only** (see §6.5). The first draft recommended persistence on the
  mistaken belief that the snapshot carries `nodes[]`. Making them durable would
  need a real serialization/replay path (the log the document is rebuilt from never
  sees them) plus a roll-off rule, which is a larger change than this spec covers.
  #3169's report §8.3 already chose view-only. If "why did this pane go quiet an
  hour ago" turns out to matter, that is a follow-up with its own design.
- **Q2. Placement.** Arrival-order append (recommended, §4.4) vs. splice after the
  originating tool node.
- **Q3. Tag wording.** `ambient` (current word, keeps continuity) vs. something
  more self-explanatory such as `AgentMux`. Recommendation: keep `ambient` and rely
  on the tooltip; the term is already used in the product.
- **Q4. Deterministic template instead of Haiku** for the `background_task` kind —
  raised in #3169 and still open. Independent of this spec, but the visual change
  makes the sentence quality more visible, since it now reads as the agent's own
  words.
