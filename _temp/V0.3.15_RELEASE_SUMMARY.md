## What Was Fixed

### 1. Color Interpolation for Debug Console (v0.3.13)
**Problem:** Debug console logs displayed as plain text without using structured color information.

**Solution:**
- Send structured JSON (`LogEntry`) from Rust instead of plain strings
- Parse JSON in UI with level and category metadata
- Apply CSS colors based on log level

**Result:** Debug console now shows color-coded logs:
- Debug: Gray (#888888)
- Info: Blue (#4A90E2)
- Success: Green (#7ED321)
- Warning: Orange (#F5A623)
- Error: Red (#D0021B)

### 2. ANSI Color Decoding (v0.3.14)
**Problem:** Terminal UI and debug console showed raw ANSI escape codes instead of colors.

**Solution:**
- Installed `ansi-to-html` npm library
- Replaced basic regex parser with comprehensive ANSI decoder
- Configured with dark theme colors

**Result:** Terminal properly renders all ANSI codes from Claude CLI output.

### 3. Claude Stdin Issues (v0.3.15)
**Problem:** When user typed input and pressed Enter, Claude didn't respond.

**Root Cause Analysis:**
- PTY writer may have been consumed after first use
- Claude's interactive menu expects specific input (Enter/arrows, not text)
- Missing terminal environment variables
- Settings file auto-trust not working as expected

**Solutions Implemented:**
1. **PTY Writer Fix**
   - Use mutable lock to allow repeated `take_writer()` calls
   - According to portable-pty docs, each call creates new writer from OS handle

2. **Terminal UX Improvements**
   - Removed Send button (Enter/Esc only)
   - Added arrow key support (↑↓) for menu navigation
   - Sends ANSI escape sequences directly to PTY:
     - `\x1b[A` for up arrow
     - `\x1b[B` for down arrow
   - Updated placeholder: "Enter to confirm, ↑↓ to navigate, Esc to clear"

3. **Environment Variables**
   - Added `TERM=xterm-256color`
   - Added `COLORTERM=truecolor`
   - Ensures Claude's TUI renders correctly

4. **Better Logging**
   - Improved settings file creation logging
   - Shows full paths when directories/files are created

### Key Insights

**Claude's Interactive Menu:**
```
╭────────────────────────────────────────╮
│ Do you trust the files in this folder?│
│                                        │
│ > 1. Yes, proceed                      │
│   2. No, exit                          │
│                                        │
╰────────────────────────────────────────╯
   Enter to confirm · Esc to exit
```

- Option 1 is **already selected** (shown by `>` cursor)
- Instructions say "**Enter to confirm**" (not "type 1")
- Arrow keys navigate between options
- Enter confirms current selection
- Typing "1" + Enter is likely invalid input

### PTY Implementation

**Before (Broken):**
```rust
let pty = pty_master.lock().await;
match pty.take_writer() {  // Consumed writer
    Ok(mut writer) => { /* write */ }
}
```

**After (Fixed):**
```rust
let mut pty = pty_master.lock().await;  // Mutable access
match pty.take_writer() {  // Creates new writer each time
    Ok(mut writer) => { /* write */ }
}
```

**Why it works:** According to portable-pty documentation, `take_writer()` creates a *new* writer from the underlying OS handle each time it's called. It doesn't permanently consume anything.

### Arrow Key Support

**Implementation:**
```typescript
else if (e.key === 'ArrowUp') {
  e.preventDefault();
  if (ws && ws.readyState === WebSocket.OPEN) {
    ws.send('\x1b[A');  // ANSI up arrow
  }
} else if (e.key === 'ArrowDown') {
  e.preventDefault();
  if (ws && ws.readyState === WebSocket.OPEN) {
    ws.send('\x1b[B');  // ANSI down arrow
  }
}
```

Sends raw ANSI escape codes directly through WebSocket to PTY, allowing Claude's TUI to process arrow key navigation.
